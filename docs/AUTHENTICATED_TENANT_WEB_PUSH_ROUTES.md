# Authenticated tenant Web Push routes\n\n`TenantPushSubscriptionWSGI` provides a mountable WSGI route component:\n\n- `GET /api/push/subscriptions` — list only device IDs/status/expiry for the authenticated tenant+subject.\n- `POST /api/push/subscriptions` — register/rotate one browser subscription.\n- `DELETE /api/push/subscriptions/{device_id}` — revoke one owner-local device.\n\n## Security boundary\n\nThe route does not accept tenant or subject IDs from request bodies, query strings or arbitrary identity headers. The host must inject `context_resolver`, backed by its already-authenticated server-side session/JWT/identity middleware, and `mutation_authorizer`, which must enforce the deployment's CSRF/origin policy for cookie-authenticated POST/DELETE requests. Missing/invalid identity returns 401; failed mutation authorization returns 403. Responses are `no-store` and do not disclose endpoint URLs or subscription encryption keys.\n\nThe WSGI component returns `None` for unrelated paths so a host can mount it before/alongside its existing application router. It is intentionally not auto-mounted into the legacy `app.py`: that module currently has no configured production tenant identity resolver, durable shared subscription backend, or CSRF policy. A deployment must explicitly compose it with `TenantPushSubscriptionRegistry` from `build_tenant_web_push_components`.\n\n## API payload\n\nPOST body shape: `{ "device_id": "browser-1", "subscription": { "endpoint": "https://…", "keys": { "p256dh": "…", "auth": "…" }, "expirationTime": null } }`.\n\nBody limit is 8 KiB. Endpoint host, HTTPS, P-256 public key and 16-byte auth secret are validated by the registry. The endpoint itself and keys are stored encrypted. The host still needs a concrete production durable backend, real secret manager, service worker, browser permission UX and real-device delivery tests. No production delivery is claimed.
